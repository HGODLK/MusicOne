# QQ 真实听歌时长同步（2026-10-25）

## 范围与接入

本轮用户明确授权新增默认不启用的可选播放会话接口并接入 QQ／酷狗。QQ 包在 `QqServices` 的媒体服务上主动实现 `SourcePlaybackSessionProvider`，`playbackSessions` 返回包内 `QqPlaybackSessionSync`；公共接口和其他音源不由本包改动。此包需要配套本轮 SDK／宿主，不将接口符号可用性扩大为对旧宿主的二进制兼容承诺。

包版本为 `1.0`／code1，入口、Android 清单和分发元数据保持原版本；仅修改功能，不自行升级版本号；公共与包内按主任务要求分开提交。

`reportPlayed` 保留原最近播放请求。时长观察者独立处理 START／PAUSE／RESUME／PROGRESS／END；仅 PAUSE 和 END 提交新增片段。输入依据是宿主提供的会话累计真实收听 `playedMs`，不使用播放位置或歌曲总长估计听歌时长。重复、乱序和回退累计值不会重复入账；毫秒尾数在同一会话后续结算中累计，不向上补足一秒。最后不足一秒的尾数不提交。

会话固定音乐账号 ID 与登录代次，同一账号正常续期可继续；换号、退出或重新登录令旧会话失效。同一会话后续事件可补全歌曲数字 ID、MID、时长等资料。手机横竖屏及平板使用同一宿主播放计时，无页面级计时器。

## QQ 包内协议

1. 优先消费本次真实 PLAYBACK 取源返回的 vkey，只保留一个最新票据引用；预取和批量缓存不登记听歌票据。
2. 缓存播放没有当前票据时，通过原 `music.vkey.GetVkey/UrlGetVkey` 请求真实标准票，仅用于统计；不调用完整播放解析、权益探测、媒体检查或交互验证重试，不改变播放器资源或音质。
3. 数字歌曲 ID 缺失时，仅通过歌曲详情模块补充资料；不调用原完整权益与封面补全路径。
4. 包内 `music.getSession.session/GetSession` 获取匿名设备 uid／sid。首次 `caller=2`，跨自然日携带旧 uid 且 `caller=1`。会话与音乐账号登录分离，按本包已有稳定设备 ID 保存并复用；设备型号与系统版本来自实际 Android `Build`，协议版本与本包现有 14090008 保持一致。
5. 用 `cmd=1`、账号、真实数字 songid／vkey、歌曲总时长及新增实际秒数构造 XML。`play_duration_mi` 与该片段毫秒数一致；timekey 使用网关协议的 MD5 计算。gzip 后提交 `https://stat6.y.qq.com/android/fcgi-bin/imusic_tj`；解析五个零字节前缀后的 zlib JSON 回执，业务 `code=0` 才确认网关接收。

不复制参考示例的固定 VIP 等级、虚构播放页时间、网络类型、音效或设备环境。统计失败只记脱敏错误类型，不打断正常播放、不输出 Cookie／账号／设备／票据原文。

## 重复与失败处理

准备设备会话、歌曲资料或票据失败时，不消耗待结算累计量，同会话下次 PAUSE／END 可继续尝试。网关没有已确认的幂等键，已发送片段在发出前锁住；网络超时、业务拒绝或回执丢失不会重发该片段，避免已入账请求因重试重复累计。正常续播产生的新片段仍可提交。

END 后会话关闭，不持久化旧账号的统计补报队列。强杀进程、END 前断网或已发出但未确认的请求存在统计损失；这些边界不得宣传为离线必达或恰好一次入账。网关确认接收不等于账号今日时长已即时更新，服务端风控、入账与展示延迟需真实账号读回确认。
